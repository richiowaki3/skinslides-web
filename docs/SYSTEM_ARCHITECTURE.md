# skinslides システムアーキテクチャ

このドキュメントは、skinslides がどのような仕組みで動いているかを解説するものです。
実装の変更履歴や作業指示については [`DEVELOPMENT/`](DEVELOPMENT/) を参照してください。

skinslides は、複数の映像解析結果と音響解析を **10軸の質感ベクトル空間** に統合し、
再生中の音声トリガー（オノマトペ）に基づいて映像を動的に選択するインタラクティブ映像作品です。

---

## システムの全体像

システムは大きく4つの層で構成されています。

```
層1: 解析データ (52映像 + 47音声トラック)
  ↓
層2: 10軸ベクトル空間への変換
  ↓
層3: オノマトペ辞書と語トリガー（再生時）
  ↓
層4: 映像選択エンジン + ライブマップ表示
```

---

## 層1：解析データの形態

### 映像ファイル（52本、各約30秒）

各映像には以下のメタデータが紐付けられています。

- **`logic_weights.json`**：手付けスコア（0–9）
  - Weight（重さ感）／ Time（時間性・速度感）／ Space（空間性・広がり）／ Hardness（硬さ・衝撃度）
- **`Video analysis data/metadata_cv2.json`**：OpenCV 身体解析
  - 平均身体速度／平均接地面積／手足の分離度／姿勢の拡張度
- **`Video analysis data/metadata.json`**：姿勢推定解析
  - 重心の移動距離／姿勢変化の頻度／最大動き強度／身体の接触点数
- **`pauseTime.xml`**：フリーズフレーム情報
  - 各映像の指定フレームで一時停止（フィボナッチ秒：1, 1, 2, 3, 5秒）

### 音声ファイル（47本）

各トラックは `Audio analysis data/sound_metadata.json` に以下を持ちます。

- トリガーイベント（時刻・種別・強度・**対応するオノマトペ語**）
- 音響プロファイル（ダイナミックレンジ／主周波数／攻撃的な音と持続的な刻みの比率）
- トラック全体の10軸ベクトル（後述）

---

## 層2：10軸ベクトル空間への変換

52本の映像それぞれに対して、前述のデータを組み合わせて以下の10軸を計算します
（`tools/build_lexicon_map.js`）。

| 軸 | 計算式 | 意味 |
|---|---|---|
| x1: Weight | 0.6×手付け + 0.4×(1−身体速度)×9 | 重さ感・持ちの重さ |
| x2: Time | 0.5×手付け + 0.5×身体速度×9 | テンポ感・即応性 |
| x3: Space | 0.4×手付け + 0.4×拡張度×9 + 0.2×手足分離×9 | 空間的な広がり |
| x4: Flow | ((1−フリーズ率)×0.5 + 重心移動×0.5)×9 | 流れのなめらかさ |
| x5: Hardness | 0.5×手付け + 0.5×最大強度×9 | 硬さ・衝撃度 |
| x6: Moisture | 接地面積×9 | ぬめり・柔軟度 |
| x7: Frequency | 4.5（固定） | 映像側は情報を持たないため中立固定 |
| x8: Decay | (フリーズ率×0.6 + 最大強度×0.4)×9 | 減衰・静かさへ向かう度合い |
| x9: Reynolds | (姿勢変化×0.6 + 手足分離×0.4)×9 | 乱流度・複雑さ |
| x16: Regularity | 姿勢変化×9 | 規則性・反復度 |

各軸は52本中の相対位置として0〜9に正規化され、手付けスコア（主観）と解析データ（客観）を
ブレンドします。音声トラックの10軸は同じ空間に投影されますが、計算式は音響指標
（オンセット密度・ダイナミックレンジ・周波数など）から独自に算出され、
`sound_metadata.json` に直接保存されています。

x7（Frequency）は映像側では定数のため、映像↔語・映像↔音の距離計算では除外します。

---

## 層3：語（オノマトペ）辞書と動的トリガー

システムは日本語オノマトペの辞書（`Audio analysis data/onomatopoeia_dictionary.csv`）を
持ち、各語も同じ10軸ベクトルを持ちます。

例：

- 「ぐいぐい」：力強く引っ張る感じ（Hardness 高、Flow 連続）
- 「ちまちま」：細かく、頻繁に（Space 小さい、Time 短い）
- 「えっちらおっちら」：ぎこちなく、少しずつ（Flow 低、Regularity 低）

各音声トラックの `triggers.events` には、時刻ごとに検出されたオノマトペ語が記録されて
います。再生中、エンジンは現在の再生時刻に対応するトリガー語を取得し、その語の10軸が
映像選択の重みに影響します。

---

## 層4：映像選択エンジン（オノマトペ駆動）

「test-level2」（パイプ状に映像が連結して流れるシーン）での、次に再生する映像を選ぶ処理は
以下のステップで行われます（`pickNextPipe()` / `pipeApplyOnomaBias()`）。

1. **辺フィルタ**：パイプは a/b/c/d の4方向を持ち、現在の映像の出口辺と次の映像の入口辺が
   一致する候補だけに絞り込みます。この絞り込みは**最重要のロジックであり、変更しません**。
   結果として b/d・d/b の組み合わせが自然に多くなります。
2. **距離計算**：辺フィルタで絞られた候補について、各映像の10軸と現在のトリガー語の10軸との
   ユークリッド距離を計算します（x7 は除外）。
3. **相対順位重み付け**：候補集合内での距離順位を係数（最大 `PIPE_ONOMA_BIAS` = 1.8倍
   〜最小 1/1.8倍）に変換します。候補の除外はしません。
4. **加重ランダム選択**：計算された重みで確率分布を作り、ランダムに次の映像を決定します。

この設計により、パイプの辺接続ルールは一切変更せず、その上に「語との親和性による確率の
偏り」だけを乗せています。600手のシミュレーション検証では、連結違反0件、全52本使用、
均等度は 0.953 → 0.963 に向上、語との質感距離は 3.6〜8.6% 改善しました。

### Play B コラージュ

「Play B」では6つのタイルが同時に映像を再生し、音声のトリガーで入れ替わります。
最低滞在時間（通常6秒、一部を短くする「一瞬枠」は1.2秒）と、まだ描画されていない枠を
押し出さない自己抑制により、「絵が出ないまま消える」問題を解消しています。

---

## 層5：ライブマップ表示

`tools/lexicon_map_data.json` には181ノード（映像52 + 語82 + トラック47）が登録されて
います。各ノードは10軸ベクトル、PCAによる2D投影座標、他ノードとのエッジ（関係性）を
持ちます。再生時、選ばれた映像とトリガー語がマップ上で光り、両者を繋ぐ関係が可視化
されます（`lexicon_live.js`）。

## 実例：映像01-Sss720p.mp4 と 音声T522.mp3

具体的な数値でシステムの動作を見てみます。

### 映像01の解析

| 項目 | 値 |
|---|---|
| 尺 | 32.4秒 |
| 姿勢 | standing |
| 方向 | Right → Left |
| フリーズフレーム | なし |

**手付けスコア**：Weight 4 / Time 3 / Space 6 / Hardness 6（いずれも0–9）

**計算された10軸ベクトル**

| 軸 | 値 |
|---|---|
| Weight | 5.76 |
| Time | 1.80 |
| Space | 5.62 |
| Flow | 7.38 |
| Hardness | 7.50 |
| Moisture | 2.79 |
| Frequency | 4.50（固定） |
| Decay | 3.60 |
| Reynolds | 1.08 |
| Regularity | 1.80 |

質感の総合評価：力強く、素早く、シャープ。だが複雑性は少なく、すっきりしている。

### 音声T522の解析

| 項目 | 値 |
|---|---|
| 尺 | 175.2秒 |
| ダイナミズム | 60.5 |
| トリガー密度 | 9.93/分（刻み41回・アタック19回） |

**計算された10軸ベクトル（保存値）**

| 軸 | 値 |
|---|---|
| Weight | 0.96 |
| Time | 4.83 |
| Space | 4.19 |
| Flow | 3.23 |
| Hardness | 4.77 |
| Moisture | 4.86 |
| Frequency | 4.90 |
| Decay | 2.46 |
| Reynolds | 3.50 |
| Regularity | 4.81 |

質感の総合評価：軽く、きれいで、安定している。刻みが支配的でリズミカル。

### 両者の関係性

10軸ユークリッド距離（x7 除外）：

| 比較 | 距離 |
|---|---|
| 映像01 ↔ T522（音色10軸そのもの） | 8.91 |
| 映像01 ↔ T522（トラック内の語の頻度加重平均） | 7.51 |

語を経由すると近づく、という点が重要です。T522に出現する語（ぐいぐい8回、えっさえっさ7回、
ちゃらんぽらん7回、がっかり6回、りゆーん6回、いらいら6回、がみがみ5回、
えっちらおっちら4回）のうち、映像01に最も近いのは「えっちらおっちら」（距離6.60）です。
一方、T522で最も多く出現する「ぐいぐい」は映像01から最も遠い語（距離9.98）です。

つまり同じT522が流れていても、「ぐいぐい」の瞬間には映像01は選ばれにくく、
「えっちらおっちら」の瞬間には選ばれやすくなる、という時間的な多様性が生まれます。

なお、全82語の中で映像01に最も近いのは「ちまちま」（距離5.29）ですが、この語は
T522には出現しません。これはこのシステムが完全一致ではなく確率的な親和性で
動くことを示す一例です。

## まとめ

1. **解析の多層性**：手付けスコア（主観）＋ OpenCV（客観）＋ 姿勢推定（詳細）の3源泉を統合
2. **10軸の統一空間**：映像・音声・語を同じ軸で比較できる、共通の「距離」という言語
3. **オノマトペの役割**：ランダム性を単に多様化するのではなく、再生中の音の質感を映像選択に
   反映させる意図的なマッピング
4. **ルール遵守の設計**：パイプの辺接続ルールは保護されたまま、オノマトペはその上に乗る
   形で拡張されている
5. **リアルタイム可視化**：ライブマップにより、システムの選択プロセス自体を作品として提示

技術的な実装詳細・変更履歴・作業指示は [`DEVELOPMENT/`](DEVELOPMENT/) を参照してください。
